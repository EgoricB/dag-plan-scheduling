Граф предшествования действий

Стрелка A → B означает: B назначается только после завершения A. Это не последовательность расписания и не траектория манипулятора. Показаны все рёбра исходного JSON, включая транзитивные. Длительность в вершине — только операция, без перемещения. Завершение учитывается на границе синхронной стадии; окончание операции внутри стадии отдельно обозначается как ожидание. Выполнение предшественников само по себе не гарантирует допустимость назначения: дополнительно проверяются удержание и геометрические ограничения.

Расписание по синхронным стадиям

Одна строка — одна синхронная стадия. Интервал отсчитывается от начала задания. Время каждого манипулятора разделено на перемещение, операцию и ожидание границы стадии. Переключатель выше одновременно меняет граф и таблицу.

СтадияИнтервал, сЛевый манипуляторПравый манипуляторДлительность, с
Δt = max(dₗ / v + τₗ, dᵣ / v + τᵣ)

d — расстояние перемещения, v — скорость, τ — длительность операции. Для неназначенного манипулятора вклад в максимум равен нулю: он ожидает всю стадию. Следующая стадия начинается после завершения обеих назначенных операций.

Визуализация сохранённых журналов вычислительного эксперимента. Выбор момента времени не изменяет расписание; Python-код в браузере не выполняется.

3. Алгоритмы и модель

Алгоритмы построения расписания

01

Общая модель допустимости

Оба режима используют один DAG, типы действий, состояния манипуляторов и общий генератор назначений, допустимых в принятой модели. Граф загружается из подготовленного JSON вместо генерации LLM.

02

Базовая политика

Сначала выбираются назначения с максимальным числом занятых манипуляторов, затем минимизируется сумма расстояний до целей. Предпочтение параллельности — допущение реконструкции, а не дополнительный член авторской функции J.

J = d(left) + d(right)
03

Модификация: минимум времени завершения

Вместо локального выбора ближайших действий алгоритм сравнивает полное оставшееся время для всех допустимых назначений.

V(s) = mina ∈ A(s) { Δt(s, a) + V(F(s, a)) }
s — состояние
Множество завершённых действий, последние действия манипуляторов (задающие их текущие позиции) и удерживаемые объекты.
A(s) — допустимые назначения
Пары действий для левого и правого манипуляторов с учётом предшественников, удержания, числа требуемых манипуляторов и геометрических ограничений модели. Один манипулятор может ожидать; назначение, в котором оба бездействуют, исключено.
Δt(s, a) — длительность стадии, с
Максимум времени «перемещение + операция» среди назначенных манипуляторов. Для каждого из них это d / v + τ: d — расстояние, v — скорость, τ — длительность операции. Более быстрый манипулятор ожидает границу стадии.
F(s, a) — переход
Состояние после завершения стадии: обновляются выполненные действия, позиции и удержание объектов.
V(s) — оставшееся время, с
Наименьшее время завершения всех оставшихся действий из состояния s. Для завершённого задания без удерживаемых объектов V = 0. Для состояния без допустимого завершения V = +∞.

Алгоритм рекурсивно оценивает назначения и сохраняет значения состояний в кэше (мемоизация). В принятой модели это точный поиск; по умолчанию он ограничен восемью физическими действиями.

На иллюстративном сценарии базовый выбор даёт 9 + 11 = 20 с. Модификация совмещает длительные операции и получает 11 + 2 = 13 с, хотя суммарное перемещение возрастает с 2 до 3 условных единиц. Следовательно, минимум расстояния не тождествен минимуму времени.

Это критерий учебной модификации данного проекта, а не утверждение о воспроизведении полной системы из статьи. Выигрыш во времени исполнения сопровождается ростом затрат на вычисление плана.

Ограничения и область применимости

  • Реализован учебный алгоритм планирования на основе DAG-Plan. Полная робототехническая система и авторский бенчмарк не воспроизведены.
  • Используется двумерная синхронная модель без проверки столкновений траекторий, отказов навыков и поступления новых заданий.
  • Цепочки удержания и рабочие зоны проверяются в рамках упрощённых допущений; применимость на физическом роботе не оценивалась.
  • В обоих режимах отсутствуют обращения к LLM. Снижение токенных затрат не является результатом эксперимента.
  • Точный поиск ограничен малыми графами. Сокращение времени исполнения достигается ценой увеличения затрат на планирование.
